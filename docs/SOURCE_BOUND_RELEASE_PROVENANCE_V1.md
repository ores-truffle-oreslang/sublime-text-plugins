# Source-bound candidate receipts and main-only signed provenance v1

This workflow separates two kinds of evidence. The `candidate-receipt` job runs
on PRs with `contents: read`, checks out the immutable PR head, checks physical
source identity, builds a deterministic Sublime archive and uploads a **candidate
manifest**. Its JSON is untrusted until checked against GitHub-authoritative
workflow metadata, source Git objects and the actual artifact bytes. It is
**not** a signature, independent review, compiler execution or authorization.

The separate `signed-main-release` job only runs for pushes to `refs/heads/main`
and only after a successful candidate job. Its credentials can request a GitHub
OIDC certificate and write a signed artifact provenance attestation for the
archive SHA-256 through pinned `actions/attest@1e69f48...`. On PRs it is
skipped, so unreviewed PR scripts are never granted those privileges.

The manifest records repository, event, numeric run/attempt, runner job **key**
(not GitHub numeric job ID), exact source head/tree and raw archive hash/size.
The SHA256 of the *uploaded Actions artifact ZIP container* is different from
the SHA256 of the raw Sublime package file. A future trusted verifier must
match both appropriately and verify the signed Sigstore certificate identity,
workflow/run, subject digest and repository provenance before promoting the
archive's integrity. GitHub's upload-artifact digest alone is not a signature.

## Required release controls that this change does not provide

- Independent authorized CODEOWNER approval and protected main with no bypass.
- External verification of artifact attestation (e.g. `gh attestation verify`
  against the intended repository and workflow identity).
- A verified numeric GitHub job ID and job-attempt match from GitHub REST.
- Main-source trust and strong release authorization beyond provenance.
- AttoLang compiler-backed guest parity. This concerns editor package output.

Signed provenance generated by a workflow on an unprotected branch may still be
cryptographically valid, but is **not evidence of a reviewed source commit**.
Keep merge automation fail-closed until governance and verification are enforced.

### Negative controls

`python3 -m unittest discover -s tests -p 'test_source_bound_release_receipt_v1.py' -v`

Reject wrong heads (including same-tree different commits), malformed context,
wrong push ref/SHA, untrusted Git environment, symlinked/hardlinked/empty/large
artifacts, traversal paths and existing receipt destinations. Assert that
candidate manifests never claim signature verification or merge authorization.
